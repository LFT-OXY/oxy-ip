# 第三方 IP 交叉核验目录与查看提示

**规格状态：** 正式规格与测试边界已获用户确认；用户运行 `/atw-implement` 后按单任务、不拆票据完成实现、验证与双轴审查，等待用户最终验收。

**分诊标签：** `ready-for-agent`。仅表示规格已整理，不替代用户确认或启动实现；事项仅保存在本地 ATW 任务目录。

## 问题陈述（Problem Statement）

用户查看本站 IP 检测结果后，需要前往第三方网站交叉核验。各站分别侧重综合风险、归属与用途、滥用与信誉或流量趋势，仅列站名无法说明应查看哪些信息。若提示不完整，用户也可能把低风险分、未命中威胁、未识别代理或聚合流量统计误当作安全、住宅属性或目标网站可用性的保证。

实现前，首页与 IP 详情没有本规格要求的九站目录；IP 查询无结果时不渲染详情内容，因此目录不能仅依附成功结果才能使用。

## 解决方案（Solution）

在首页和 IP 查询页提供内容一致的九站目录。每站默认显示网站名及一句简短用途，用户可独立展开详细查看提示，再通过独立外链前往第三方网站。本站只提供导航与解释，不查询第三方、不追加待查 IP，也不合成安全结论。

### 展示位置与状态

- 首页专区位于 IP／分流结果之后、平台检测之前，按“综合查询、归属与用途、滥用与信誉、流量趋势”四类呈现。
- IP 查询已有结果时，目录位于“IP 情报（威胁指标）”之后、“地理位置 · 多源对比”之前；允许比首页更紧凑，但不得遗漏站名、用途、链接或提示。
- 首页目录不依赖检测成功；IP 查询页未查询、加载中或失败且无数据时，目录位于搜索区下方。存在缓存结果时沿用有结果位置，同一页面不重复显示目录。
- 用途为一句简短文案，不要求物理单行；窄屏及英文较长时自然换行，不截断。
- 详细提示初始收起，各站可同时独立展开，不持久化展开状态。
- 外链在新标签页打开，保留本站结果，并提供外链标识。
- 支持中英文，站名与目标网址不因语言变化；译文保留完整风险限定。

### 验收条件

- **AC1 — 完整性：** 首页和 IP 查询页各显示九站且无重复；首页四组数量依次为 3、2、3、1，成员与表一致。
- **AC2 — 放置：** 首页及有结果详情的目录分别处于上述位置；无结果时目录在搜索区下方。查询开始、成功、失败或缓存刷新均不造成重复目录或目录缺失。
- **AC3 — 内容一致：** 两处九站名称、用途、目标网址和详细提示一致；中文用途与表一致，详细提示完整覆盖表内限定。
- **AC4 — 默认与展开：** 目录首次挂载时九站提示均收起；打开任意一站后仍可打开另一站；关闭其中一站不影响另一站；不主动保存或同步展开状态。
- **AC5 — 操作独立：** 点击或键盘激活展开控件只改变对应提示，不打开外链；激活链接只发起外链导航，不改变提示。两类控件均可独立聚焦，焦点可见，语义及可访问名称清楚。
- **AC6 — 固定导航：** 九个链接使用表内固定网址，不追加待查 IP、查询串或片段；新标签页打开并使用 `noopener noreferrer`。IPQS 不提供额外登录入口。
- **AC7 — 无自动第三方访问：** 本功能的渲染、展开或查询状态变化不发起第三方请求；不增加第三方 API、预取、远程图标等自动访问。用户主动外链导航不受此限制；不改动本站既有检测请求。
- **AC8 — 解释边界：** 不把外部故障、分数、威胁未命中、代理未识别或流量统计推导为单个 IP 的安全保证、住宅属性保证、目标网站可用性或 Cloudflare 验证结论；保留九站各自具体提示。
- **AC9 — 语言与布局：** 中英文均有用途和完整提示，英文不回退成遗漏翻译的中文；桌面与移动端、深浅主题下可读可操作，文案自然换行，不因截断或横向溢出丢失信息。
- **AC10 — 回归与范围：** 原有搜索、最近查询、加载／错误提示、结果展示与检测行为不被改变；不新增通用折叠状态模块或测试框架。

## 用户故事（User Stories）

1. 作为首页访客，我希望在 IP／分流结果后找到第三方核验专区，以便顺着检测结果继续核对。
2. 作为首页访客，我希望按四类用途浏览网站，以便选择与当前疑问相关的工具。
3. 作为 IP 详情读者，我希望在风险情报之后看到第三方入口，以便对照本站风险信息。
4. 作为跨页面用户，我希望首页和详情提供相同九站及说明，以免因入口不同而得到不一致指引。
5. 作为尚未查询的用户，我希望仍能使用目录，以便直接选择外部工具。
6. 作为等待查询的用户，我希望目录不被加载状态阻挡，以便不必等待本站结果。
7. 作为遇到查询失败的用户，我希望仍能跳转第三方，以便继续自行核验。
8. 作为看到缓存结果的用户，我希望刷新时目录不重复，以便保持页面清晰。
9. 作为首次使用者，我希望默认看到站名和简短用途，以便不展开长文也能判断入口是否适合。
10. 作为希望深入了解的用户，我希望主动展开详细提示，以便了解应查看的字段与解释边界。
11. 作为比较工具的用户，我希望同时展开多个网站说明，以便来回对照而不用反复切换。
12. 作为阅读提示的用户，我希望展开不会跳转，以便留在本站继续阅读。
13. 作为准备核验的用户，我希望点击链接不会被折叠控件拦截，以便直接访问目标网站。
14. 作为交叉核验者，我希望外链在新标签页打开并有外链标识，以便保留本站结果作比较。
15. 作为键盘用户，我希望链接和展开控件均可独立聚焦、激活，以便不依赖鼠标完成操作。
16. 作为使用辅助技术的用户，我希望两类控件具备正确语义及清楚名称，以便区分导航和展开行为。
17. 作为手机用户，我希望用途及提示自然换行且完整可读，以便不因小屏幕遗漏重要限制。
18. 作为英文界面用户，我希望得到与中文同等完整的说明，以免风险边界在翻译中丢失。
19. 作为深色主题用户，我希望文字与焦点仍清晰可见，以便正常阅读和操作。
20. 作为 CleanIP 使用者，我希望知道站点暂时不可访问并不说明当前 IP 不安全，以免把外部故障当成风险结论。
21. 作为 IPSuper 使用者，我希望知道不同数据源可能不一致，以便不单凭总分定性。
22. 作为 MeowVPS 使用者，我希望知道需要自行选择或输入地址，且数据可能不完整，以免误认为本站已代填并完成核验。
23. 作为 IP2Location 使用者，我希望分清 Region、Usage Type、AS Usage Type 与 ASN，以免把注册主体或用途分类当成住宅／机房的直接证明。
24. 作为 IPLark 使用者，我希望理解代理未识别及服务限制，以免把缺少信息当成确定结论。
25. 作为 IPQS 使用者，我希望直接进入公开查询页并理解滥用和风险信号，以免误入登录入口或把低分当成安全保证。
26. 作为 ipdata 使用者，我希望理解 Threats 为 0 的有限含义，以免据此断言安全、住宅属性或目标网站可用性。
27. 作为 Scamalytics 使用者，我希望区分欺诈风险意见与垃圾邮件评分，以免误读总分或低分。
28. 作为 Cloudflare Radar 使用者，我希望理解流量统计的聚合范围及机器人流量的含义，以免推断单个 IP 家宽概率或是否触发验证。
29. 作为关注查询边界的用户，我希望链接不附带本站待查 IP，目录也不自动请求第三方，以便由我主动决定前往何处查询。
30. 作为目录维护者，我希望两处复用同一份内容，以便后续修改不会导致站名、网址或风险提示漂移。

## 实现决策（Implementation Decisions）

- 采用一个供首页与 IP 查询页复用的业务目录展示单元，统一维护九站分组、站名、固定网址、用途与提示。只保留实际布局差异，不建立通用目录框架、插件系统或后台配置。
- 首页接入分组目录；有结果详情在风险情报后接入目录；IP 查询页无结果分支在搜索区下方接入同一目录。页面根据既有数据有无决定位置，目录本身不依赖 IP 查询结果或当前地址。
- 使用原生锚点承担导航，使用原生 `details/summary` 承担提示展开。站名链接位于展开触发区之外，不以整张卡片点击代替两类控件，不通过事件拦截弥补相互嵌套。
- 每站展开状态由浏览器原生控件管理；不使用互斥分组，不引入全局状态、持久化或通用折叠管理模块。普通页面更新无需强制重置提示；首次挂载保持收起。
- 外链提供明确标识、使用新标签页和 `noopener noreferrer`，不在目标网址上构造待查 IP 参数。
- 按现有翻译机制提供中文和英文文案；站名、字段名与专有缩写保持准确，不能用统一免责声明替代各站说明。
- 复用现有卡片、间距、主题及响应式样式约定；用途与提示允许换行，保留可见键盘焦点及原生控件可访问性。
- 本次仅变更目录展示、两页接入、相关文案及必要测试；不改变后端接口、响应结构、查询缓存或风险评分算法。

## 测试决策（Testing Decisions）

### 已获用户确认的测试边界

以首页和 IP 查询页实际渲染的目录为主要验收边界：观察用户可见内容、导航目标、提示开合与页面状态，不测试组件内部状态、私有函数名或文件组织。不为了测试增加应用接口或通用状态层。

浏览器验证实际交互与布局；沿用现有 Node 测试补目录内容契约及英文覆盖回归。不新增测试框架，也不以第三方网站是否在线作为通过条件。本规格不要求交付新建的浏览器自动化测试套件。

### 覆盖范围

- 目录内容：九个唯一站名、九个固定目标、四组成员和用途／提示完整性；两页内容一致。应有可重复运行且能发现内容契约破坏的回归检查，而非只搜索源码是否出现站名。
- 页面接入：首页，以及 IP 查询的空白、加载、成功、失败无数据、缓存结果刷新场景。可以在本地控制响应或使用现有缓存机制构造状态，不依赖第三方服务制造失败。
- 交互：初始全部收起、多站同时展开、独立关闭、点击及键盘分别激活链接和提示、焦点可见；导航目标和新标签页行为正确。
- 自动请求边界：区分既有网络检测请求与本功能新增请求，确认目录渲染、展开和查询状态变化没有引入对九站的自动访问。可拦截外链请求确认意图，不要求远端页面加载成功。
- 文案：中英文均覆盖各站风险限定。人工语义核对与自动覆盖检查互补，不能把存在翻译键视为翻译含义正确。
- 布局：移动／桌面、中英文、深浅主题，检查长文换行、溢出、独立控件可操作性及内容不被遮挡。
- 回归：既有搜索、最近查询、加载／错误展示仍按原行为工作；运行项目构建、lint 及现有测试，完整测试前先构建。

### 既有测试先例与证据要求

- 项目使用 Node 自带测试与断言；现有内容测试包含静态目录成员、导航契约及构建产物断言，可沿用其外部内容契约测试思路。
- 现有国际化测试检查字面量翻译调用、英文条目及占位符，并验证英文运行时行为；动态目录文案不能落入未被检查的覆盖盲区。
- 现有源码／构建产物检查不构成浏览器交互测试。已执行的自动回归、实际浏览器检查与未验证范围分别记录在 `research/verification.md`，不将 Node 内容测试当作交互证据。
- 不进行生产部署，不通过访问外站评分判断本站功能是否通过。

## 范围之外（Out of Scope）

- 新增、替换第十个站点，或增加 IPQS 登录入口。
- 自动预填 IP、复制并代填第三方表单、第三方 API 接入、抓取、评分聚合或联动刷新。
- 第三方可用性监控、自动重试、故障评级，以及通过远程图标或预取自动访问第三方。
- 根据任何第三方结果自动给出安全、住宅／机房、目标服务可用性或 Cloudflare 验证预测。
- 更改本站已有风险评分、类型判断、检测请求、路由、搜索或缓存逻辑。
- 收藏、筛选、搜索、用户自定义站点、展开状态持久化或跨页面同步。
- 通用折叠状态管理、新的 UI／测试框架、后台管理与无关页面重构。
- GitHub Issue 同步、生产部署与对第三方服务能力或可用性的实时背书。
