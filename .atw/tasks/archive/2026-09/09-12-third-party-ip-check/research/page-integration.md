# 页面接入探索

## 已核实事实

- `src/views/home/index.tsx`：首页依次为 IP 概览与网络连通性、`SplitResults`、`PlatformSummary`、`QuickChecks`、`BrowserSummary`、热门功能。当前文件没有第三方 IP 核验目录。
- `src/views/ip/details.tsx`：详情依次包含类型/ASN/技术/风险卡片、IP 情报（威胁指标）、地理位置多源对比、延迟、地图、关联域名与历史/关联地址，末尾为全球延迟测试按钮。当前文件没有九站目录。
- `src/views/ip/index.tsx`：只有 `query.data` 存在才渲染 `IpDetails`；无数据时仅渲染查询头部、搜索和最近/推荐查询。加载与错误提示位于条件分支之前；缓存数据可能与刷新错误同时存在。
- `src/i18n/index.ts`：支持 `zh-CN` 与 `en`；通过 `t()` 查询 `src/i18n/en.json`，未命中英文翻译时回退原文。
- `src/views/ip/location-map.tsx` 等现有外链采用新标签页；项目已有 `noopener noreferrer` 用法。
- `src/views/whois/index.tsx`、`src/views/ping/index.tsx` 已有原生 `details/summary` 使用实例。
- `.atw/spec/frontend/quality-guidelines.md`：现有 Node 测试不证明浏览器交互；涉及 UI 需额外核对移动/桌面、深浅主题、键盘焦点、中英文。完整验证先构建再测试，不进行部署。

## 第一轮用户已确认

1. 首页专区放在 IP／分流结果之后，即 `SplitResults` 之后、`PlatformSummary` 之前。
2. 有查询结果时，详情目录放在“IP 情报（威胁指标）”之后、地理位置多源对比之前。
3. 始终提供目录：未查询、加载中或查询失败且无结果时，IP 查询页在搜索区下方显示目录；首页专区也不依赖检测成功。
4. “一行用途”表示一句简短用途，窄屏及英文较长时允许自然换行，不截断信息。

## 用户最终确认的沿用方案

- 沿用现有新标签页外链方式，保留本站结果；明确外链标识并使用 `noopener noreferrer`。

- 固定链接不追加待查 IP，不自动请求、抓取、汇总或检测第三方站点。
